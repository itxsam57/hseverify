# M1.06 Subunit 4 Regression Addendum

These stable IDs extend the HSE Verify regression register for defects discovered while building M1.06 Subunit 4. They remain permanent even if the signed preview/download implementation or engineering tooling is later refactored.

| ID | Defect prevented | Root cause | Required behaviour | Permanent automated guard | Status |
|---|---|---|---|---|---|
| REG-055 | Malformed signed capability timestamps reach integer/time arithmetic without first proving their runtime type | The first token parser passed untrusted JSON fields directly to integer checks, relying on TypeScript casts/narrowing rather than proving `iat` and `exp` are numbers at the runtime boundary | Signed token parsing must require numeric `iat` and `exp` before safe-integer, lifetime, future-skew or expiry checks; strings, fractional values and malformed times fail closed | `src/lib/secure-files/secure-file-access-domain.ts` explicitly proves numeric types; `tests/secure-files/secure-file-access-domain.test.mjs` rejects string/fractional/malformed timestamps | PROTECTED |
| REG-056 | Historical/corrupt display filename metadata injects path/control characters into `Content-Disposition` even though the filename was validated earlier in the upload lifecycle | The first response-header draft assumed accepted stored metadata could never be damaged later and encoded it without re-running the canonical filename validator at the final response boundary | Stored display filename must be revalidated immediately before header construction; the ASCII fallback remains server-generated, while the validated stored filename is emitted only as an encoded UTF-8 parameter. Control/path characters fail closed | `src/lib/secure-files/secure-file-access-core.ts` reuses `normalizeSecureFileDisplayFilename`; `tests/secure-files/secure-file-access-core.test.mjs` covers CR/LF and path injection plus Unicode/quote encoding | PROTECTED |
| REG-057 | The signed-access unit gate removes the production `server-only` boundary merely to make standalone Node tests compile | The first isolated strict test compiler did not know Next's marker-only `server-only` module, so TypeScript stopped before unit execution | Production signed-access modules must retain `import "server-only"`; the isolated test compiler gets only a test-scope ambient module declaration, and the runner removes only the emitted marker import from its temporary compiled copy after strict compilation | `tests/types/server-only.d.ts`, `tsconfig.secure-access-tests.json` and `scripts/run-secure-access-tests.mjs` preserve production source while allowing isolated strict unit execution; full project typecheck/build still validate the real server-only imports | PROTECTED |
| REG-058 | The signed-access source guard rejects safe bounded audit metadata such as `byteSize`, encouraging removal of useful audit facts merely to obtain a green gate | The first guard searched the entire adapter with an unbounded case-insensitive `bytes` substring, so the letters at the start of `byteSize` were misclassified as raw file bytes | The guard must classify identifier semantics: bounded byte counts such as `byteSize`/`byteLength` are allowed, while raw byte collections, tokens, URLs, object keys, hashes, storage authority and secrets remain forbidden in the audit adapter | `scripts/check-secure-file-access.mjs` self-tests allowed and forbidden identifier families and scans the real audit adapter using the same semantic predicate | PROTECTED |
| REG-059 | Mandatory AI/build context says old bricks are still in progress or not started after those bricks have already been accepted, allowing a future developer to branch from the wrong milestone boundary | Volatile milestone state was duplicated across `PROJECT-PROFILE.md`, `PROJECT-TEST-MATRIX.md`, `HSE_BUILD_MEMORY.md`, `MILESTONE_PATH.md` and `LATER.md`, while `check:engineering` only proved that files/keywords existed and still hard-coded an old M1.04 handoff marker | The exact current gate, permanent milestone record, compact memory, profile, test matrix and Later register must agree on M1.01–M1.05 acceptance, M1.06/Subunit state and canonical M2/M3 counts; resolved Later items must not remain open; CI must fail on contradictory/stale markers | `scripts/check-engineering-automation.mjs` cross-checks the authoritative context set and canonical roadmap markers during every quick/full gate | PROTECTED |
| REG-060 | Signed-access route-surface and migration rollback/reapply tests exist in the repository but never execute, allowing a green gate without proving those required contracts | The first runtime runner invoked only the PGlite access and audit tests; newly added `secure-file-access-routes.test.mjs` and `secure-file-access-migration-stack.test.mjs` were orphan test files not referenced by any executable gate | Every permanent signed-access platform test must be invoked by the signed-access integration runner that is itself required by `test:integration` and the complete gate | `scripts/run-secure-access-runtime-tests.mjs` invokes runtime, audit, migration-stack and route-surface tests together; the engineering/source gate protects that runner wiring | PROTECTED |

Additional defects discovered by CI or self-review must receive the next stable regression ID before Subunit 4 can close.
