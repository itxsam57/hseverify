# M1.07 Subunit 1 Regression Addendum

Stable regressions discovered while building the Worker Identity Domain, Versioned Persistence and State Machine. These guards remain permanent after Subunit 1 closes.

| ID | Defect prevented | Root cause | Required behaviour | Permanent automated guard | Status |
|---|---|---|---|---|---|
| REG-073 | Adding durable Worker identity history makes the already-accepted authentication foundation no longer independently reversible beneath later layers | The first `0015_worker_identity_foundation.up.sql` used direct foreign keys from `worker_identities.worker_account_id` and `worker_identity_versions.created_by_account_id` to `auth_accounts`. M1.07 rollback is intentionally monotonic and keeps identity history, so after 0015 is logically rolled back those physical FKs still prevented `0002_authentication_foundation.down.sql` from dropping `auth_accounts`. Using `CASCADE` or deleting identity rows would merely hide the incompatibility by destroying accepted history | Worker/account identifiers stored in immutable identity history are durable historical references, not physical foreign keys to a rollback-owned authentication schema. Creation must validate an active Worker account/role in SQL, every repository command must revalidate the live Worker session/account/role transactionally, identity ownership identifiers must remain immutable, and the accepted M1.03 independent rollback/reapply test must continue unchanged. Production/preview destructive rollback remains prohibited | `database/migrations/0015_worker_identity_foundation.up.sql` contains no `REFERENCES auth_accounts`; `worker_identity_validate_insert()` validates the active Worker account and role; `src/lib/identity/worker-identity-repository.ts` revalidates the live Worker session/account/role inside each transaction; `tests/platform/authentication-foundation.test.mjs` keeps its existing `authentication migration remains independently reversible beneath later layers` test unchanged; `scripts/check-worker-identity-foundation.mjs` permanently rejects an identity→`auth_accounts` FK | PROTECTED |

Additional serious defects reproduced during Subunit 1 receive the next stable ID before the unit can close.
