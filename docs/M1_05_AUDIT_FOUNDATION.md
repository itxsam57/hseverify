# M1.05 Subunit 1 — Immutable Audit Foundation

## Status

**IMPLEMENTATION IN REVIEW**

This subunit builds only the immutable platform audit domain, schema, append-only repository and authorized query contracts. It does not build transactional outbox processing, background workers, notification surfaces, notification deep links or email delivery.

## Implemented boundary

1. Explicit wildcard-free audit action, outcome and target vocabularies.
2. Opaque native audit identifiers and database-generated native timestamps.
3. Trusted actor binding from accepted server authorization principals only.
4. Optional trusted Company tenant and membership snapshots.
5. Credential-safe, bounded and deterministic metadata validation.
6. Migration `0007_platform_audit_foundation` with append-only database enforcement.
7. One-time backfill and transactional mirroring of accepted `auth_security_events`.
8. Native append repository with no update or delete command.
9. Platform reads restricted to `platform.security.read`.
10. Company reads restricted to the active tenant and `company.audit.read`.
11. Direct tenant predicates, bounded pagination and non-enumerating find behavior.
12. Rollback/reapply, persistence, concurrency-adjacent identity, immutability and source-contract tests.

## Security decisions

- Browser input cannot set actor account, role, tenant, membership, permission, outcome authority or timestamps.
- Native timestamps are generated by the database.
- Existing authentication timestamps are retained because they were generated by the accepted server authentication boundary.
- Audit records intentionally do not use destructive foreign-key cascades; opaque actor and tenant references remain historical facts.
- Database triggers reject every update and delete, including attempts outside the application repository.
- Sensitive metadata keys such as passwords, OTPs, tokens, secrets, cookies and authorization values are rejected for native events and stripped from the compatibility bridge.
- No UI is an authorization boundary.
- Root and Administrator platform audit reads still revalidate the live session and account.
- Company audit reads reuse the accepted transactional tenant command guard.
