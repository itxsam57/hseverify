## Exact objective

Add a separate integrity evidence system around an active Worker assessment. The engine records authorized normalized observations, detects insufficient/degraded monitoring, derives advisory integrity classification and exposes a safe evidence timeline for later human review.

It is evidence infrastructure, not a scoring or adjudication system.

## Mandatory security/data invariants

1. Integrity session attempt/Worker/form lineage is database constrained.
2. One integrity session exists at most once per assessment attempt.
3. Raw device nonce and lease token are never persisted; only server-side SHA-256 digests are stored.
4. Binding uses trusted authorization `sessionId` plus bounded browser-generated assessment nonce; auth session id never comes from browser input.
5. One authoritative active lease/device binding exists at a time; competing live bindings fail closed.
6. Integrity events are append-only at the database boundary.
7. Sequence number and receipt time are assigned server-side.
8. Idempotency key reuse with identical payload converges; same key/different payload conflicts.
9. Browser/provider signal vocabulary and source/signal combinations are allowlisted.
10. Event metadata is bounded and allowlisted; secrets, answer bodies, raw media and unrestricted diagnostic objects are rejected.
11. Policy/version/classification/degraded state are server-derived.
12. Provider/required-monitoring failure creates explicit degraded evidence and never silently yields a clean classification.
13. Red is advisory evidence; it cannot mutate assessment outcome.
14. High-volume telemetry stays out of generic platform audit.
15. Evidence timeline never exposes digests, raw tokens/nonces, raw provider output, hidden thresholds or answer content.
16. Emergency Exit remains operable if telemetry/media/reporting fails.
17. Final assessment submission may end the integrity session but does not score/adjudicate.
18. M2.05–M2.08 behavior remains green.
