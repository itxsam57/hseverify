## Scope accepted

- one server-authoritative mutable draft for the Worker's authoritative current uncommitted question;
- typed draft persistence that preserves cleared values, whitespace, and partial numeric edit states without reusing committed-answer storage;
- compare-and-swap revision control plus bounded idempotent mutation retry behavior;
- live owning-Worker authorization with server-resolved attempt/form/item/question lineage and client position/question-version values treated only as stale guards;
- a safe current-draft reload projection containing only the current draft value, revision, and update time alongside the already-safe current question;
- atomic committed-answer behavior in the existing M2.07 transaction: explicit submitted answer remains authority, the matching draft is deleted, then progression/final submission occurs, with downstream failures rolling the transaction back;
- an owned `IN_PROGRESS` resume listing exposing only safe attempt/case/catalogue/position/count/timestamp metadata and never a draft body;
- a server autosave action that accepts only bounded draft/stale-guard/mutation inputs and returns coarse safe acknowledgement state without Worker/form/item/question authority or raw-draft logging;
- a truthful client autosave state machine with saved/saving/error/conflict behavior and no browser-persistent answer cache;
- Save and exit, bounded Emergency exit, and Resume assessment UI paths over the same server authority;
- permanent M2.08 targeted and real-Chromium regression coverage;
- exact PR-head checkout enforcement for M2.08 browser, M2.07 browser, and Independent audit workflows.
