## Exact objective

Close M2.05 as an evidence-backed immutable form-generation layer. The server must generate the complete Worker-specific form from an exact blueprint version, exclude every stable question previously shown to that Worker, pin exact question versions and authoritative order, fail closed on missing/mismatched policy or insufficient unseen capacity, and deliver only answer-safe question fields. Admin blueprint management must work through the real isolated Admin portal.

## Security and data-integrity constraints

- Worker identity used for generation is derived from the Assurance Case.
- Exact blueprint framework must match the immutable case policy snapshot framework.
- Stable question and exact question version must be a valid parent/version pair.
- Stable blueprint and current blueprint version must be a valid parent/version pair.
- Generated form and all ordered items must commit atomically and remain append-only.
- Correct answers, written rubrics, fingerprints, creator ids, nonce, and internal audit data must never enter the delivery projection.
- Admin blueprint mutations require live, unrevoked Admin authority.
- Audit metadata must not expose hidden scoring material or nonce.

## Mandatory acceptance criteria

1. Same Worker receives zero repeated stable `question_id` values across generated forms, including after question revision.
2. Different Workers may receive the same stable question.
3. Exact generation-time question version is pinned and remains the delivered version after later revision.
4. Only active stable questions and their matching current exact versions are selectable.
5. Cross-framework or missing-policy-snapshot generation is denied with no partial form.
6. Insufficient unseen selector capacity fails with zero partial form rows.
7. Concurrent same case + blueprint generation converges to one immutable form/item set.
8. Blueprint/current-version and question/current-version cross-parent pointers are rejected by the database.
9. Form item question/version cross-parent pointers are rejected by the database.
10. Item positions/count cannot exceed the immutable form definition, and incomplete/noncontiguous forms cannot commit.
11. Blueprint versions, generated forms, and form items reject UPDATE/DELETE history tamper.
12. Delivery DTO contains no answer key, rubric, fingerprint, creator id, nonce, or internal audit data.
13. Admin blueprint create/revise/status controls work through real visible Chromium UI and survive reload.
14. No decorative/dead M2.05 controls remain.
15. Temporary repair workflows are absent from the accepted head.
